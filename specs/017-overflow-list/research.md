Takeaways:

- Three ways to fill the menu: a render callback (Blueprint, Mantine, rc-overflow), authored twins (Fluent), or rows built from the items (Spectrum, Primer, Carbon). For a web component that has no render prop, building rows from the children and forwarding activation to them (Carbon) is the one that works with plain markup.
- The libraries that re-render to measure flash and thrash. The cheap ones keep hidden items laid out and measured where they are (rc-overflow), then do one greedy pass. `c2-chip-group` already does exactly that with manual slot assignment and a 0×0 measuring layer.
- Reserve the trigger only while something is hidden, but keep it measurable when it is not (rc-tabs keeps it `visibility: hidden`), so showing it never needs a second pass.
- `collapseFrom` defaults to end everywhere but Blueprint. Priorities and pinning are Fluent's; Carbon's `data-fixed` is the same idea as an attribute.
- None of them keeps focus when the focused item folds.

## 2. Accessibility

- [Menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/): the trigger is a button with `aria-haspopup="menu"` and `aria-expanded`; Enter / Space / ArrowDown open on the first row, ArrowUp on the last. `c2-menu` does all of it for a slotted trigger.
- [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/): one Tab stop with arrow keys, labelled, for three or more controls; the APG example contains a menu button. Not built in (see open questions); the author can set `role="toolbar"`, and the list's own role is `group`.
- APG "Persistence of focus": when the focused element is hidden, browsers move focus to `body`. The list must move it somewhere sensible: the trigger.
- Hidden items must leave the tab order and the accessibility tree (rc-overflow `aria-hidden`, Primer `tabIndex=-1`, Fluent and Carbon `display: none`).
- Trigger names in use: "More items" (React Spectrum, Primer), "More page actions" (Carbon), "Show N more items" (breadcrumbs), "More items, including current item" (Primer). No guidance on announcing the count; a counted name is the common choice.
- For navigation links APG prefers a disclosure to `role=menu`. Not adopted in v1: menu rows are commands that click the link, as in Primer's `ActionList.LinkItem` inside an `ActionMenu`.

## 3. What c2 already has

- `c2-chip-group`: the measuring technique (manual slot assignment, invisible 0×0 layer, ResizeObserver per child), `overflow-change` with `visibleCount` / `hiddenCount`, `hiddenItems`. Reused as is.
- `c2-menu` / `c2-menu-item`: the whole menu (positioning, keys, typeahead, checkbox rows, `menu-select`). The list renders a `c2-menu` in its shadow root with a native trigger, as `c2-split-button` does.
- `c2-breadcrumb`: collapses a path behind an ellipsis by its own rules; not replaced.
- `c2-action-bar`: actions scroll sideways with edge fades; an overflow list can sit inside it.
- `c2-page-header` (spec 016) planned its own "More actions" folding and noted it could move here later without an API change.
