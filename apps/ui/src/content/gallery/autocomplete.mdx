## Record picker

`multiple` turns the field into a lookup that keeps several records as chips, `creatable` adds a row that asks the app to create the record the query names, and `recent-items` fills the panel before anything is typed. The advanced search dialog of a full record picker is an app composition of `c2-modal` and `c2-table`, opened from the `footer` slot.

<AutocompleteExamplesRuntime />

The "create" row only asks: the app creates the record (on its server, in a dialog) and hands it back with `pick()`, which adds it as a choice would. `renderPick` replaces a chip's label, and its output may fill the chip's `prefix` slot.

```ts tag=CodeBlock
import { html } from 'lit'

labels.addEventListener('create-request', async ({ detail }) => {
  const label = await api.createLabel(detail.query)
  labels.pick(label)
})

attendees.renderPick = ({ item }) => html`<c2-avatar slot="prefix" name=${item.name} auto-color aria-hidden="true"></c2-avatar>${item.name}`
```

## Custom row renderer

The live cards above assign `renderItem` as a property. The autocomplete still creates and controls each `c2-list-item`; the renderer supplies only the row content and may use the list-item slots.

```ts tag=CodeBlock
import { html } from 'lit'

autocomplete.renderItem = ({ item }) => html`
  <c2-avatar slot="prefix-icon" name=${item.name} status=${item.status} auto-color aria-hidden="true"></c2-avatar>
  <span>${item.name}</span>
  <span slot="description">${item.role} · ${item.location}</span>
  <c2-badge slot="suffix-icon" tone=${item.status === 'online' ? 'success' : 'neutral'}>
    ${item.status}
  </c2-badge>
`
```
