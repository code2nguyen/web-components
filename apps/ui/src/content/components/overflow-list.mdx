`c2-overflow-list` lays its children out on one row that never wraps. The children that do not fit fold into a "More" menu at the end, and come back as soon as there is room. It is the "priority+" pattern behind page header actions, mail and editor toolbars, and repository tabs. The row refits when the list is resized, a child's size changes, or children are added and removed. It works in a single pass over sizes it already knows, because folded children stay laid out out of sight.

The menu is built from the folded children, in document order. Each row is named after its child (`data-overflow-label`, then `aria-label`, then its text) and shows a copy of the child's icon. A disabled child gives a disabled row, and a toggle gives a checkbox row. Activating a row clicks the child itself, so its click listeners, form submission and link navigation work as they do in the row. `<hr>` and `c2-separator` children divide groups, both in the row and in the menu. `c2-menu-item` rows slotted into `menu` are always listed after the folded children.

The list reads its children and never writes to them:

- `data-overflow="pinned"` keeps a child in the row whatever the room.
- `data-overflow-priority="2"` makes a child outlast the ones around it.
- `collapse-from="start"` folds from the other end, for example for a long path.
- `min-visible` and `max-visible` bound how many children show.

When the child that has focus folds, focus moves to the trigger. The trigger is named after the count ("3 more items"). It says "including current item" when a folded child carries `aria-current` or is a `selected` link.

Give the list a width: it is a block, so it fills its container. In a flex row, set `flex: 1` and `min-width: 0` on it.

## Import

```typescript tag=CodeBlock
import '@c2n/components/overflow-list'
```

Importing `@c2n/components/overflow-list` also registers `c2-menu` and `c2-menu-item`. The examples use the separate `@c2n/feather-icons` package: `npm install @c2n/feather-icons`.
