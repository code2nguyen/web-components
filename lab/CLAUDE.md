# Component lab

Guidance for `lab/`. Claude Code loads this file when it works in this directory; the repo-wide rules are in the root `CLAUDE.md`. Paths are relative to the repository root.

`lab/` — the **component lab**: specs of apps (`lab/specs/`), builds of them made only from c2n components (`lab/apps/`), build reports, journeys run by personas with deterministic checks (`node lab/scripts/lab.mjs run|replay`), run records in `lab/runs/` and the gap matrix (`lab/GAPS.md`). `lab/README.md` documents it, the `component-lab` skill runs it, the `Component lab replay` workflow replays it weekly, and the docs site shows it at `/lab`. Each build also feeds AI readiness: `.mcp.json` sets `C2N_MCP_LOG` so the `c2n` server logs its calls to `lab/.armed/mcp-calls.jsonl` while that file exists (`node lab/scripts/readiness.mjs --arm <spec>/<direction>` creates it for one build, `--disarm <spec>/<direction>` deletes it), `node lab/scripts/readiness.mjs <spec>/<direction> --log …` keeps that log next to the report and writes the report's generated AI readiness section (how each component was found), and `mcp:readiness` scores the reports' met and workaround rows as "Lab requirements" discovery, outside the headline. Not a workspace package.
