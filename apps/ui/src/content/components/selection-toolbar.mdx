`c2-selection-toolbar` wraps content and shows a small toolbar over any text selected in it, like the selection bubbles of Notion and Medium, the "Add comment" button of Google Docs, or "Ask ChatGPT" on a selection. The app slots in the controls; the toolbar positions them, keeps the selection while they are pressed, and makes them reachable from the keyboard.

## Import

```typescript tag=CodeBlock
import '@c2n/components/selection-toolbar'
```

### When it shows

The toolbar appears once a selection inside the content is complete: when the pointer is released, or after a short pause in a keyboard selection. The selection needs at least `min-length` characters (1 by default), once trimmed. The toolbar sits centred above the selection; `placement="bottom"` puts it below, and it flips when there is no room. It renders in the top layer, so no overflow or z-index clips it, and it follows the selection on scroll. It hides when the selection collapses or leaves the content, and on Escape. `disabled` turns it off.

### Acting on the selection

Pressing a control keeps the selection, so `selection` (`{ text, range }`) can still be read in its click handler. A control with `data-action` also fires `selection-action` with that action and the selected text, so one listener can serve every button:

```js tag=CodeBlock
toolbar.addEventListener('selection-action', (event) => {
  if (event.detail.action === 'comment') openThread({ quote: event.detail.text })
})
```

`selection-change` fires when the toolbar shows for a selection or its selection changes, and `toggle` fires when it opens or closes.

### Keyboard

The toolbar never takes focus on its own. When it appears, a screen reader hears "Actions available, press Alt+F10". Alt+F10 moves focus into the toolbar, the convention of TinyMCE, CKEditor and Google Docs. The arrow keys move between its controls, Home and End go to the ends, and Escape returns focus to where it was.

### Inline prompt

`prompting` turns the toolbar into a prompt anchored where it stands, like Notion AI or "Help me write": the `prompt` slot (a field, quick actions) and the `result` slot (the answer, then Replace, Insert below, Retry, Discard) replace the toolbar's controls. A control with `data-prompt` sets it from markup. Focus moves to the first field, and the selection stays frozen while the reader types: `selection` still holds its text and range, and every `data-action` control in the prompt fires `selection-action` with that text. With no selection, `prompting = true` anchors to the caret in the content, so an editor can open it from a shortcut, or to the content itself.

The prompt is a non-modal dialog: Tab moves between its controls, and the arrow keys stay with its field.

The application owns the model and the answer: it streams into an element it puts in the `result` slot (a `c2-streaming-text`), which shows once it is there, and applies the answer through `selection.range`. Escape closes the prompt and returns focus; `toggle` with `open: false` is the moment to abort the request. The prompt stays open, at its first anchor, while the reader clicks or selects elsewhere, so a streaming answer is never lost; close it from Discard with `prompting = false`.

```js tag=CodeBlock
toolbar.addEventListener('selection-action', ({ detail }) => {
  const range = toolbar.selection?.range
  if (detail.action === 'replace' && range) {
    range.deleteContents()
    range.insertNode(document.createTextNode(answer.value))
    toolbar.prompting = false
  }
})
```

### Limits

It acts on selections in the page's own text. Selections inside form fields belong to those fields, and by default so do selections inside other components' shadow roots; set `composed` to act on those too (an answer drawn by `c2-markdown`, the text of `c2-text-annotator`). Chromium and Firefox report such a selection directly; WebKit reports a caret next to the component, which the toolbar resolves with `Selection.getComposedRanges()` (Baseline newly available, feature-detected).
