# Research: `c2-master-detail`

Roadmap #69 (section D, P2). Collected 2026-10-24 before design; decisions and API in [spec.md](./spec.md). Mock: [c2-master-detail mock](https://claude.ai/artifact/1gsjtT6ssND3oV154ktGpA) (desktop split, tablet overlay, phone stack, anatomy and API sketch; the first three are clickable).

## 1. Prior art

| System                                                                     | Shape                                                                                                                                                                                             | Narrow behaviour                                                                                                                                                              | Notes                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Vaadin `vaadin-master-detail-layout` (`@vaadin/…` 25.3.4)                  | Default slot = master, `detail` slot, `detail-placeholder` slot. `master-size` (default 30em), `detail-size` (measured from content when unset), `orientation`, `expand-master` / `expand-detail` | The detail becomes an **overlay** over the master when both do not fit (`overlay` state attribute), `overlay-size`, `overlay-containment="layout" \| "page"`, `force-overlay` | Fires `backdrop-click` and `detail-escape-press` but **does not close itself**: the app removes the detail. Has a placeholder that is hidden (not overlaid) when it does not fit. Writes state attributes on the host (`overlay`, `has-detail`). |
| Material 3 list-detail canonical layout / Android `ListDetailPaneScaffold` | List pane + detail pane                                                                                                                                                                           | Compact and medium: **one pane at a time**; selecting swaps in the detail, Back returns to the list. Expanded: both, selection updates the detail in place                    | Resizing keeps state: narrowing keeps the open detail (hides the list); widening shows both, the detail area becomes a placeholder when nothing is open.                                                                                         |
| SAP Fiori Flexible Column Layout                                           | Up to three columns; `layout` enum (`OneColumn`, `TwoColumnsBeginExpanded`, `TwoColumnsMidExpanded`, `MidColumnFullScreen`, `ThreeColumns…`)                                                      | Phone: one column, navigation by route                                                                                                                                        | Layout is set per route by the app; "Enter full screen" on the detail column. Heavier than a component: it is a page frame.                                                                                                                      |
| Ionic `ion-split-pane`                                                     | Menu + content                                                                                                                                                                                    | `when="md"` media query: below it the side pane becomes a menu                                                                                                                | Viewport media query, not the element's own width.                                                                                                                                                                                               |
| Products                                                                   | Gmail, Outlook, Apple Mail, Linear inbox, Slack threads                                                                                                                                           | Mobile: list, tap → full-screen detail with a back arrow at top start; tablets: Outlook keeps the list, Mail overlays it                                                      | Selection stays highlighted in the list while the detail is open (split); keyboard j/k moves through records in place.                                                                                                                           |

Takeaways:

- Three layouts cover everything: **split**, **stack** (one pane, Back) and **overlay** (detail over a still-visible master). Vaadin only has split + overlay, Material only split + stack; offering both narrow modes is cheap.
- The detail's content and "what is selected" are the app's. Every system leaves selection to the app; the layout only needs a boolean "something is open".
- Who closes the detail differs: Vaadin only reports Escape and backdrop clicks. Closing on Back / Escape / backdrop but letting the app cancel it (unsaved changes) covers both camps.
- A placeholder in the empty detail column is standard (Vaadin, Material, every mail client).

## 2. What the repo does today

- `c2-split-panel` puts two panes side by side with a draggable divider, but has no narrow mode and no idea of "open".
- `c2-sheet` is a page-level modal panel (top layer, scroll lock): right for a form over the whole app, wrong for a detail confined to one region of a page.
- `c2-side-nav` reads the **window** width; the app-shell research (spec 016) already decided that layout components should read their **own** width (container queries for the first paint, `ResizeObserver` for behaviour). This component follows the same rule.
- Example apps hand-build list + detail: `support-inbox-vue` (inbox + conversation), `orders-admin-angular` (orders + order), `log-lens-nextjs` (log list + log inspector). None of them stack on a phone.

## 3. Constraints from the repo

- Never write an attribute on the host from the component: the layout is exposed through custom states (`:state(split)` …) and a read-only `layout` property, not a reflected attribute (Vaadin's approach would break React hydration).
- Presentation (column width, divider, overlay width, toolbar look) only as `--c2-master-detail__*` variables with theme-mappable defaults.
- Built-in text ("Back", "Details") through `defineMessages`.
