## Columns and data

Every card is a `rows` array plus a set of `c2-table-column` children: `width` takes any grid track, `align` moves the text, `format` runs the value through `Intl` (`number`, `currency`, `percent`, `date`, `datetime`, `time`), and `pinned` sticks a column to either edge while the rest scrolls. A cell value is text, so a column is dressed up from CSS: `::part(cell-content-status)` is the text of the status column and takes a pill as well as any badge would. Put a component in a cell with a `renderCell` function from script.

## Sorting and selection

`sortable` makes every header a sort control and `sort="field:asc"` sets the starting order; `multi-sort` lets a shift-click add a second key. Selection is `single` or `multiple`, with `checkbox-selection` for a leading checkbox column, and `value` holds the selected row keys — `;`-separated in markup.

## Filters and comparisons

`filterable` on a column (or on the table, for every column) puts a funnel in its header. It opens a `c2-facet-list` of the column's values with their counts (the rows the other filters let through), searchable, each value included, excluded or picked alone, with the two sorts and a way to clear. Alt+↓ opens it from the header. The filters live in `filters`, a JSON attribute too, so a filtered view can be written in markup and applies before the filter's code loads; `filter-change` reports each change, and a `dataSource` receives them in its request. `baseline` takes last period's rows, matched by `row-key`: a column with `compare="delta"` or `compare="percent"` shows each cell's change from it, and `variance-threshold` marks the cells that moved further than that share.

## Realtime updates

`animate-updates` belongs to the table, so a feed assigns only its next real snapshot—even when it adds, deletes and
modifies rows in one operation. The table matches rows by `row-key`, expands additions, collapses removals and
interpolates finite numbers over `update-duration`; nested numeric arrays are included. This means the price, derived
percentage, row background and the `c2-sparkline` returned by `renderCell` all receive one synchronized intermediate
row. This example uses `rowStyle` for a persistent threshold: red at or below 30% of the day's range, green at or above
70%, and neutral between them. Prices move by no more than about 0.08% per tick, so a row keeps its regime instead of
flickering between colors. Every third replay tick performs an add or delete so all update paths stay visible.

## Toolbar and footer

The `toolbar` and `footer` slots are yours, and they are the natural place for the rest of the library: `c2-text-field` for a search, `c2-select` for a filter, `c2-button` and `c2-icon-button` for actions, `c2-badge` for a count. Both bars stay outside the scrolling body and are hidden until something is slotted into them; `--c2-table__toolbar--*` and `--c2-table__footer--*` set their padding, background and divider.

A `c2-pagination` in the `footer` is wired up rather than decorative: the table pages its rows and drives the pager's `page`, `page-size` and `total-items`, so the card below works with nothing but the two elements. With a `dataSource` the same markup pages server-side, one request per page.

## Statuses and running balances

## Editing

`editable` turns the columns that have an `editor` into a grid people type into, as in a spreadsheet: Enter, F2, a double click or typing opens one editor over the cell, Enter or Tab commits it and moves on, Escape cancels, Delete clears, and a block copied from Excel or Sheets pastes from the focused cell. The rows are never mutated: each change fires `cell-change` and `rows-change` with a new `rows` array. The toolbar's buttons call `addRow()`, `revertChanges()` and `validate()`; the editing code loads on the first edit.

"Timesheet grid" edits hours with a `c2-duration-input` (type `1h 30m`, `90m` or `1:30`), recomputes each row's total with `rowRule`, flags a missing day on a workday with `validate`, locks approved and submitted rows with `isCellEditable`, and splits the week total into regular and overtime hours. "Journal entry" keeps a line to a debit or a credit (typing one clears the other) and enables Post only once the entry balances:

```ts tag=CodeBlock
// A custom editor: any element, mounted over the cell being edited.
day.renderEditor = ({ draft, setDraft }) => {
  const input = document.createElement('c2-duration-input')
  input.value = typeof draft === 'number' ? draft * 3600 : null
  input.addEventListener('input', () => setDraft(input.value === null ? null : input.value / 3600))
  return input
}

// A row rule: runs after each edit, before the row is stored.
timesheet.rowRule = ({ row }) => ({ ...row, total: days.reduce((sum, day) => sum + (row[day] ?? 0), 0) })
timesheet.isCellEditable = ({ row }) => row.status === 'draft'

journal.rowRule = ({ row, field, value }) =>
  value === null ? row : field === 'debit' ? { ...row, credit: null } : field === 'credit' ? { ...row, debit: null } : row
journal.addEventListener('rows-change', ({ detail }) => {
  const difference = sum(detail.rows, 'debit') - sum(detail.rows, 'credit')
  post.disabled = difference !== 0
})
```
