`c2-header` owns site-shell layout without owning navigation state. Put a `c2-navigation-menu` in the default slot, use a real `c2-link-button` for navigation actions, and add as many end controls as needed to the `actions` slot. The action area handles spacing and alignment; `sticky` pins the shell and `blurred` adds its translucent backdrop treatment.

A `sticky` header knows when page content scrolls beneath it: the host matches `:state(stuck)`, fires `stuck-change`, and `--c2-header__stuck--box-shadow` applies, so the shell can stay flat at the top of the page and lift once it overlaps content. Add `hide-on-scroll` to slide it away while the reader scrolls down and bring it back on the way up or when focus moves into it (`:state(retracted)`, `retract-change`). The behaviour is shared with `c2-sticky`, which does the same for a toolbar, tabs or an action bar further down the page.

## Import

```typescript tag=CodeBlock
import '@c2n/components/header'
```

The examples use icons from the separate `@c2n/feather-icons` package: `npm install @c2n/feather-icons`.

## Usage

The navigation menu owns desktop panels and its responsive trigger, while the header remains responsible for brand, layout and page-level actions.
