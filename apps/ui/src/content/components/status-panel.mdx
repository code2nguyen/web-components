`c2-status-panel` presents a meaningful application state without assuming that the state is empty or the result of an operation. Choose a `status` for the built-in media treatment, provide concise copy through attributes or slots, and add actions or supporting content only when they help the user move forward.

Assigned slot nodes are light DOM and take ordinary classes. Use the matching `::part(media)`, `::part(title)`, `::part(description)`, `::part(content)`, or `::part(actions)` selector for the component-owned region around each slot. The first three parts also style their visible fallbacks; content and actions remain stable but hidden when empty.

## Installation

```bash tag=CodeBlock
npm install @c2n/status-panel
```

The `media`, `title`, `description`, `actions` and `content` slots accept any composition. `heading` and `description` are convenient text fallbacks; slotted content takes precedence. Set `heading-level` to match the surrounding document hierarchy. The component is not a live region by default—add `role="status"` for a dynamically completed operation or `role="alert"` only when an error requires immediate attention.

The default `neutral` status suits empty and unavailable states. `info`, `success`, `warning` and `error` change the built-in icon and its semantic colour treatment. Use `align="start"` for detail-heavy panels and customize the container, media and content surfaces with the documented CSS variables.
