`c2-tool-call` shows one step an AI agent took with a tool, the way Claude and ChatGPT show theirs: the tool's name and what the call did on one line, with its state, and, when opened, the input the tool was called with and the output it returned. A run of agent steps is a column of them, usually inside a `c2-chat-message`.

`state` moves the card through `pending` (queued, or its input still streaming in), `running`, `success`, `error` and `cancelled`. Each state has its own mark and a translatable word in the header, so the colour is never the only signal; `duration` adds how long the call took.

## Import


### Input and output

`input` and `output` take any value, as a property or as JSON in the attribute: text shows as it is and anything else as indented JSON; an attribute is read as JSON only when it holds an object or an array, so a tool that printed `null` or `7` shows exactly that, in a box that scrolls past `--c2-tool-call__code--max-height` and joins the tab order only when it does. A failed call shows `error-text` in place of the output, under an Error heading. The `input` and `output` slots replace the formatted values with richer content, such as a `c2-json-viewer` for a large result or rendered Markdown.

### Approval

Content in the `actions` slot sits under the header and stays visible while the card is closed, which is where Approve and Deny go when a call waits on the user. The card does not decide anything: listen to your buttons, then set `state` to `running` or `cancelled`.

### Accessibility

The card is a native details element: the header is a disclosure button that opens and closes it from the keyboard, and a screen reader hears the tool's name, what it did, the duration and the state's word, then whether the card is expanded. The opened sections are labelled Input and Output (or Error). Every state is also a custom state, so `c2-tool-call:state(error)` styles the failed ones from the page.
