# Style-contract audit results (diagnostic checkpoint; full gate deferred)

This is an implementation checkpoint, not a passing verification ledger. `verify:style-contracts` now emits a deterministic, schema-checked failed-property ledger, but the complete browser and configuration-panel evidence runners are not implemented yet.

The paused checkpoint was revalidated in a clean `develop`-based worktree: `npm ci`, root `npm run build`, direct `npm run build -w apps/ui`, `npm run docs:check`, `npm run test:type-check`, `npm run lint`, and `npm run format:check` pass. The style-contract tooling suite passes 57/57, the Chromium contract suite 108/108, and the UI configuration-panel suite 10/10. The full static audit still intentionally exits nonzero with 2,724 findings, so the full verifier and CI gate remain deferred.

## Verified checkpoints

- Fifty-seven discovery/model/static/inspector/exception tests pass, including all five seeded contract defects, compiled-Sass default drift, per-tag stylesheet ownership, transitive private-CSS-alias consumption and cycle rejection, reviewed-exception field/date/staleness/ordinary-shadow rejection, registry field/type/staleness checks, a valid fixture, panel registration, composition, and descriptor ownership checks.
- The case-driven Chromium suite passes 108 tests. It covers one button border case, all 17 color-slider property cases, all 16 keyboard property cases, all 13 label property cases, all nine chart-tooltip property cases, both attachment-group cases, all five dashboard cases, all three mat-icon cases, one tooltip offset geometry case, five accordion properties, one avatar-group shadow, a registry-driven skeleton `::after` color case with applied state/dimensions, five shared icon-property cases, per-tag icon metadata checks with one Feather and one Phosphor runtime sample, and synthetic assertion-path and false-positive controls. The malformed-registry startup test now addresses a named case rather than assuming the first registry entry has a particular value syntax.
- Every assertion now checks that its target belongs to the tested host and that the target stabilizes before, after, and on restoring the edit. This permits finite CSS transitions while rejecting unrelated animation/layout changes. Published value types are checked even for ordinary computed-style cases, and static readiness and browser startup share complete reviewed-registry validation.
- Geometry cases now observe a reviewed metric rather than any bounding-box difference. Programmatic SVG/image probes compare rendered pixels, and dynamic cases can require an observation window to reject delayed or stepped output. Unresolved indirect values are classified as invalid test input.
- Assertions now apply a placebo host-style edit and a second valid value control, so a redraw triggered only by style mutation or property presence does not count as value-specific evidence. Hidden/non-rendered computed and text targets do not count as visible presentation. SVG bitmap capture carries live computed filter, clipping, and transform styling into the rasterized copy; unsupported raster output still fails closed.
- Bitmap probes now reject hidden/non-rendered canvas, image, and SVG targets even when their underlying pixels change; each probe also has a visible-output positive control. A case whose actual output is elsewhere must target that visible public surface.
- Reviewed cases may supply a distinct literal `controlValue` when no safe inferred second value exists. Browser validation checks it against both observed and published syntax; `justify-content` and `font-style` keyword fixtures pass, while an invalid keyword is rejected as test input. Zero-CSS-width and zero-CSS-height canvas, image, and SVG targets are rejected even while intrinsic pixels update, with visible-size positive controls for each probe.
- The static CLI now supports `--json` to retrieve all sorted failures beyond its 50-line human summary. Geometry and programmatic cases must validate their contrasting values; an invalid value reports `invalid-test-value` rather than a broken component contract.
- The keyboard component's Sass font-family fallback now retains the documented comma-separated family list; its package build and Chromium target-effect case pass.
- Rebuilt the chatbot, color-select, tabs, and steps manifests after correcting their documented defaults to match existing compiled Sass; the static default-mismatch count fell from nine to zero without changing their rendered CSS.
- The color-slider package build and all three Chromium component tests pass, including a regression test for left-border and corner-radius updates.

They verify color-slider border, color, and length edits against rendered computed styles; one-corner and linked/independent four-corner editing; kbd keyword, free-text, and font control edits; a button selected-state variable activated through the Props tab; and a composed `c2-details` variable written to the `c2-accordion` host and observed on the slotted child's header. ## CI/CD diagnostic checkpoint

The pull-request workflow now covers both `develop` and `main`, collects the full static inventory independently of changed-package test selection, and runs the current style-contract browser suite in Chromium, Firefox, and WebKit as a non-blocking diagnostic. The manual npm release and Pages deployment workflows also collect the static report before publication/deployment. Each static run uploads JSON and prints sorted failure counts in the GitHub job summary; deployment now blocks on stale generated component, open-package, and icon manifests. Existing build, docs, and changed-component behavior gates remain intact.

The pull-request Chromium job also runs the ten-case configuration-panel suite as a non-blocking diagnostic and uploads its failure traces with the other Playwright artifacts. The focused descriptor/mapping suite passes 8/8, and the panel suite passes 10/10 locally; this CI step does not yet substitute for the required complete per-property evidence gate.

This is **not** the required full-library gate: `verify:style-contracts` now exits `1` with a failed status for every property because complete browser and panel evidence is absent, and `check:style-contracts` currently exits `1` with 2,724 static failures across 6,563 properties. A prior local Firefox/WebKit diagnostic run produced 57 passes, 50 expected skips, and one WebKit failure: the synthetic externally styled SVG filter did not produce the expected bitmap change; the tooltip offset case passes separately in both engines. The browser sample suite is not yet the reviewed representative matrix. Phase 16 blocking-gate tasks therefore remain open until coverage, remediation, final ledger orchestration, and this cross-browser failure are resolved.
