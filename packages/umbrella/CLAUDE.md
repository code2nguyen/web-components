# @c2n/components (umbrella)

Guidance for `packages/umbrella`. Claude Code loads this file when it works in this directory; the repo-wide rules are in the root `CLAUDE.md`. Paths are relative to the repository root.

`packages/umbrella` — published `@c2n/components`, **the only published component package**. The component packages are private workspaces; this one bundles them. `@c2n/framework-types` (`emit-umbrella.ts`) **generates and commits** the bundle inputs under `src/` — `src/<name>.js` re-exports every JavaScript subpath of `@c2n/<name>` (so `@c2n/components/table` registers `c2-table` and `c2-table-column`), `src/index.js` re-exports every entry, `src/react.d.ts`/`vue.d.ts` import each package's `/react`/`/vue` declarations — plus `theme.css`/`base.css`/`tokens.css` (which `@import` the theme) and the `exports`/`files`/`customElements`/`dependencies`/`peerDependencies`/`devDependencies` keys of its `package.json`; the other fields, `scripts/` and the README are hand-written. Its `dependencies` are only what the bundle still imports (Lit, `@c2n/core`, `@c2n/theme`, the icon sets two components use, third-party libraries; two packages pinning one library differently stop the generator), and the component packages are `devDependencies` at `*`. `npm run build -w packages/umbrella` (`scripts/bundle.ts`, wireit, also `prepack`) builds the ignored `dist/` with Vite — one entry per component, shared modules in `dist/chunks/` so each element is defined once — copies every package's declarations into `dist/types/<name>/` with `@c2n/<inlined>` specifiers rewritten to relative paths (usage comments rewritten to `@c2n/components/…`), merges their manifests into the ignored `custom-elements.json` (module paths prefixed with the package name; the theme and framework-types generators skip `@c2n/components` so nothing is counted twice), and fails if `dist/` imports a package `package.json` does not list, or if a component imports one of Lit's own packages (`lit-html`, `lit-element`, `@lit/reactive-element`): those are not dependencies, so they would be inlined with the browser condition (`isServer` from `lit-html/is-server.js` became a literal `false` and broke SSR) — import from `lit` instead. `npm run check:bundle-size` (umbrella `size` script, a `deploy.yml` gate) measures each entry plus the chunks it reaches through static imports, gzipped, against the committed `size-budget.json` and fails past +10% and 2 kB per entry; that is what catches a dependency that stops being external or a component pulled into another's graph. A new component records its entry with `npm run size:add -w packages/umbrella`, which adds only the entries with no budget and leaves the rest alone; when growth is intended, `npm run size:update -w packages/umbrella` rewrites every entry. There is no whole-bundle total to keep in step: `lazy` budgets the chunks only a dynamic `import()` reaches, which `index` (it re-exports every entry) does not count, and which a new component does not change, so no line of the budget is shared by every component PR. `index` itself is recorded but not checked, for the same reason: it is the union of every entry, so it grows with each new component and an accident already shows in the entry it lands in. `npm run type-check -w packages/umbrella` (in `build:tools`) compiles the bundled declarations with `skipLibCheck` off: that is what catches two packages exporting the same name, which an `export *` barrel otherwise drops silently, and a specifier the rewrite missed. Its browser suite (`test/umbrella.spec.ts`) imports the barrel and checks every tag in the merged manifest is registered; `npm test` selects it for any component change, so build the umbrella first (`npm run build -w packages/umbrella`, which `component-tests.yml` runs after `npm run build`). User-facing docs (install lines, code samples, the skill, MCP import lines) always say `@c2n/components/<name>`, and so does the docs site's own code (MDX island imports, `component-modules.ts`, `chrome-modules.ts`), so the site exercises the bundle users install; `ui:build` and `npm run ui` build the umbrella first. Only the manifests (`@c2n/<name>/custom-elements.json`) are still read from the workspace packages. Never mix the two in `apps/ui`: a workspace import next to the bundle loads a second copy of the class, and the first `customElements.define` wins. Bare workspace path like `packages/core`.
