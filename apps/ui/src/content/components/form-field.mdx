`c2-form-field` wraps one form control and draws everything around it: the label with a required or "Optional" marker, a `label-action` link, the hint, the error or a non-blocking warning, and a `length / maxlength` counter. It reads `required`, `disabled`, `maxLength`, `value` and `validity` from the control, so you state those once, on the control. The `c2-*` controls receive the label and the hint or error as text and put them on their own focusable element, which `aria-labelledby` and `aria-describedby` could not reach across the shadow boundary; while a field wraps a control that draws its own hint line, the control hides it.

Errors follow "reward early, punish late": nothing shows while a field is untouched or being typed in for the first time. An error shows when a form submit finds the control invalid, on `validate()`, or on blur or input with `validate-on="blur"` / `"input"`, and from then on the field re-checks on every edit, so the error clears as soon as the value is fixed. The message comes from a server error, `error-text`, a slotted `<span slot="error" data-match="valueMissing">` for that validity key, a slotted error without `data-match`, or a built-in message in the page's language. Wrap the fields in a [`c2-form`](/web-components/components/form) for an error summary, server errors and dirty tracking.

Layout is CSS: `--c2-form-field--direction: row` puts the label beside the control and wraps it above once the control would be narrower than `--c2-form-field__body--min-width`. Custom properties inherit, so set them once on a form or any ancestor.

### Messages per validity key

The built-in messages are generic ("Fill in this field."). Give a field its own wording with one slotted `error` element per validity key; the first key that fails picks the message, and an element without `data-match` covers any other failure. The slotted text is read as text.

```html tag=CodeBlock
<c2-form-field label="Email">
  <c2-text-field name="email" type="email" required></c2-text-field>
  <span slot="error" data-match="valueMissing">Enter your email address.</span>
  <span slot="error" data-match="typeMismatch">Enter an email address like name@example.com.</span>
</c2-form-field>
```

### Native controls

A native `<input>`, `<select>` or `<textarea>` sits in the light DOM, so it can only be named by light-DOM text: use the `label` and `hint` slots, which the field links with `ariaLabelledByElements` / `ariaDescribedByElements`. The `label` and `hint` attributes render inside the field's shadow root, which a native control cannot reference.
