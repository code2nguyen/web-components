`c2-sticky` keeps a toolbar, a row of tabs, a section heading or an action bar in view while the content around it scrolls. Stickiness itself is CSS `position: sticky`, so it costs nothing at rest; what the element adds is the **stuck state**: once content runs beneath it the host matches `:state(stuck)`, fires `stuck-change`, and its surface switches to the `__stuck--*` background and shadow, so a bar can sit flat on the page until it actually overlaps something. `edge="bottom"` pins it to the bottom edge instead. With `hide-on-scroll` it slides out of view while the reader scrolls down and comes back on the way up, or as soon as focus moves into it.

The element sticks within its parent, and the nearest ancestor with `overflow` set is the box it sticks to, exactly as for any sticky box. Keep a distance from the edge with `--c2-sticky--offset` (the height of a sticky header above it, for instance), and switch pinning off under a breakpoint with `--c2-sticky--position: static`, which also switches the stuck state off. `c2-header` uses the same behaviour for its `sticky` mode.

## Import

```typescript tag=CodeBlock
import '@c2n/components/sticky'
```

## Reacting to the stuck state

Style a stuck element from outside with `:state(stuck)` and `:state(retracted)`, or listen for `stuck-change` and `retract-change`, which do not bubble. The element's `stuck` and `retracted` properties read the current state, and `reveal()` brings a retracted element back.

```typescript tag=CodeBlock
const toolbar = document.querySelector('c2-sticky')!
toolbar.addEventListener('stuck-change', (event) => {
  console.log(event.detail.stuck ? 'content runs beneath the toolbar' : 'toolbar back in the flow')
})
```

```css tag=CodeBlock
c2-sticky:state(stuck) .title {
  font-size: 14px;
}
```
