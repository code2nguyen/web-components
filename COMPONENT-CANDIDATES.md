# Component candidates: the round-three long list

A long list of 410 component candidates for c2n, researched on 2026-11-07 and checked against the library on 2026-11-10. It is the input to the next selection for [`COMPONENT-ROADMAP.md`](COMPONENT-ROADMAP.md), not a plan: nothing here is decided. Set the Decision cell of a row to **Accept**, **Reject** or **Later**, with a short reason for a rejection. Accepted rows move to the roadmap; this file can then be deleted.

The list was built for recall. The earlier rounds asked "what do design systems ship that c2n lacks"; this one asks "what do enterprise applications put on screen", domain by domain, and then sweeps the remaining catalogs for anything else.

Every row then got a recommendation under one rule: **extend an existing component when that does not harm its performance, and add a new one only otherwise.** Of the 410 rows, 232 go through a component or package that already exists (135 extensions in place, 31 extensions whose code loads on first use, 21 companion elements in an existing package, 31 presets of another row's extension, 8 already covered, 6 helpers for `@c2n/core`), 101 are compositions for the blocks collection, and 77 need a new package.

## How the list was built

Seventeen research passes each read one family of sources and compared every entry with the manifest descriptions of the 272 `c2-*` elements on `develop` (commit `14ff619c`) and with every row of the roadmap, whatever its state:

- **Six enterprise verticals**, from product documentation, help centres and release notes: finance and accounting; human resources; operations and supply chain; sales, marketing and support; IT, security and compliance; healthcare, legal, public sector, education and property.
- **Five component catalogs** that rounds one and two did not read: React and headless libraries (Radix, Base UI, React Aria, Zag, Mantine extensions, Tremor), enterprise widget suites (Kendo, DevExtreme, Syncfusion, AG Grid, Ignite UI, Bryntum), Vue, mobile and CSS frameworks (Element Plus, Vuetify, Vant, Ionic, DaisyUI, Flowbite), corporate design systems (Atlassian, Primer, Lightning, PatternFly, UI5, GOV.UK, USWDS, Orbit, Gestalt) and the animated catalogs (Aceternity, Motion-Primitives, React Bits, Kibo UI).
- **Six product sweeps**: platform-native widget sets and message-card schemas (Apple HIG, Material 3, WinUI, libadwaita, Slack Block Kit, Adaptive Cards, survey builders), developer and data tools, AI and agent interfaces, CMS and page builders, business and productivity apps, consumer apps.

The passes returned 801 rows. Rows describing the same widget were merged (the nested rule builder came back from eight passes, the tree grid from seven, the barcode scanner from seven), which left the 410 below. Another 69 rows were dropped during the merge and are listed at the end with the reason.

**Read the sources with care.** The research environment could reach GitHub and npm but not most vendor documentation hosts, so many catalogs were read from their source repositories, and product behaviour often comes from search-result snippets, not from an opened page. A Source of "—" means the row rests on product knowledge alone. Verify a row against the live product before accepting it, as round two asked for its own unlinked rows.

## The performance rule

"Does not harm performance" was judged against the gates and precedents the repository already has. The entry sizes quoted in the tables are the gzipped budgets in `packages/umbrella/size-budget.json`.

1. **Entry weight.** `npm run check:bundle-size` fails an entry that grows past 10% plus 2 kB. A feature that fits that margin goes into the component. A bigger one is loaded with a dynamic `import()` on first use, which the budget counts under `lazy` and not under the entry: `c2-image` already loads `@c2n/modal` this way for its preview, `c2-map-chart` its outlines, `c2-code-editor` CodeMirror.
2. **Hot paths.** A feature must add no work per row, per frame or per instance while it is off. Two paths matter most: `c2-table` windowing, which needs a uniform row height (`wrap` already switches it off), and the charts' data-only update path. A recommendation that touches either says how it stays clear of it.
3. **Small, repeated elements.** `c2-button` (2.4 kB), `c2-list-item`, `c2-highlight`, `c2-format-number` and `c2-date-input` appear hundreds of times on a page. They take only extensions of a few hundred bytes with no extra DOM. Anything larger becomes a companion.
4. **Nobody pays for what they do not use.** When hosting a feature would bill every user of the host (a form designer inside the 140 kB `c2-json-form`, a native select inside the 25 kB `c2-select`), it is a companion entry or a new package.
5. **Engines stay optional peers**, imported on first use.

## How to read a row

- **Priority.** **P1**: other rows depend on it, or almost every business app needs it. **P2**: common in business or consumer apps. **P3**: specialised.
- **Recommendation** is what to build, with the host component when there is one:
  - **Extend**: add it to the named component, in place. Small, opt-in, free when unused.
  - **Extend (lazy)**: it belongs to the named component, and its code sits in a chunk imported on first use, so the entry keeps its size.
  - **Companion**: a new element inside the named package, with its own entry, like `c2-table-column` or `c2-chart-legend`. It shares the host's model and costs nothing to a page that does not import it. Used where building it into the host would break rule 3 or 4.
  - **Preset**: it falls out of another row's extension. There is nothing separate to build beyond a gallery example; the note names the row it depends on.
  - **Covered**: an existing component already does it. Suggested decision: reject.
  - **Core**: a controller or helper in `@c2n/core`, not an element.
  - **Block**: a composition of existing components. It belongs in the blocks collection.
  - **New**: a new package. Either no component is close, or hosting it would harm the host.
- **How, and what it costs** says where the feature goes and why that is safe, or why it is not.
- **Numbers** continue the roadmap's (round two ended at 238) and are for reference only.

As researched: 25 rows are P1, 141 are P2 and 244 are P3. These counts are a snapshot and are not maintained.
