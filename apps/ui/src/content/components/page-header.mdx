`c2-page-header` is the top of a page. Write your heading in the default slot (usually an `<h1>`: the header styles it and never chooses its level), then fill what the page needs: `breadcrumb` (a `c2-breadcrumb`), a `leading` visual, `title-suffix` badges, a `description`, `meta` facts, page `actions`, `navigation` tabs and a `toolbar` for search and filters.

It lays out from its **own width**. Below 600px the breadcrumb gives way to a parent link ("Back to Batches", taken from the breadcrumb's second-to-last item or from the `parent` slot), the leading visual hides and the actions take their own row. Actions that do not fit fold into a **More actions** menu: those without `overflow-priority` first, from the end of the row, then by ascending priority. The action marked `primary` never folds. A folded link stays a link and a folded submit button still submits its form; other elements, such as a `c2-split-button`, never fold.

With `sticky`, once the title has scrolled away a condensed bar keeps the parent link, the title, its badges and the primary action in view. Inside a `c2-app-shell` it sits right under the shell's header with no extra CSS. A page header rendered on the server cannot fold its actions, so they wrap instead.

## Import

```typescript tag=CodeBlock
import '@c2n/components/page-header'
```

The examples use an icon from the separate `@c2n/feather-icons` package: `npm install @c2n/feather-icons`.

## Usage

The narrow frames show the parent link and folded actions; open **More actions** to see them.

