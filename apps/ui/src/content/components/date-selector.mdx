`c2-date-selector` chooses a start and end date without a time-zone conversion. The first activation starts a range,
the second completes it, and the third starts over. Use `min` and `max` for availability, `months="1"` for compact
layouts, and `locale` or `week-start` to match the audience. Arrow keys move between days; Page Up and Page Down move
between months. The calendar keeps a usable seven-column minimum width; on mobile, a two-month selector stacks the
months vertically.

## Usage

```html tag=UsageBlock,package=@c2n/date-selector
<style>
  .date-selector-compact {
    --c2-date-selector__day--size: 34px;
    --c2-date-selector--box-shadow: none;
  }
</style>

<div data-label="Date range">
  <c2-date-selector from="2026-09-10" to="2026-09-15" locale="en-US"></c2-date-selector>
</div>
<div data-label="Constrained">
  <c2-date-selector class="date-selector-compact" months="1" from="2026-10-05" min="2026-10-01" max="2026-10-24" locale="en-US"></c2-date-selector>
</div>
<div data-label="Disabled">
  <c2-date-selector months="1" from="2026-11-08" disabled locale="en-US"></c2-date-selector>
</div>
<div data-label="Single date">
  <c2-date-selector mode="single" months="1" value="2026-09-17" marked="2026-09-04;2026-09-22;2026-09-29" locale="en-US"></c2-date-selector>
</div>
```

Listen for `change` to receive `{ from, to }` in `event.detail`; both are `YYYY-MM-DD` strings. `input` fires at the
same time for generic form bindings. With `name="trip"`, a complete range submits `trip` and `trip-end`; override the
second key with `end-name`. `required` treats an unfinished range as missing.

## One date or several

`mode="single"` turns the calendar into an inline date picker: each activation replaces `value`, a single `YYYY-MM-DD`
date. `mode="multiple"` toggles dates in and out of `value`, kept in ascending order and separated by commas, and marks
the grid `aria-multiselectable`. Both leave `from` and `to` alone, add `value` to the `change` detail, submit `value`
under `name` (one entry per date in `multiple` mode), and treat an empty `value` as missing when `required`.

`marked` lists dates that carry a dot (events, availability): an array in script, or `;`-separated in markup. For more
than a dot, such as a price or an event count, set `renderDay`: it receives `{ date, day, selected, disabled, marked,
today }` for each day and returns what to draw under the number. The day button, its accessible name and the selection
stay the component's. The [gallery](/web-components/components/date-selector/gallery) shows both.

```html tag=UsageBlock,package=@c2n/date-selector
<div data-label="Multiple dates">
  <c2-date-selector mode="multiple" months="1" value="2026-09-08,2026-09-10,2026-09-15" locale="en-US" aria-label="Choose shift days"></c2-date-selector>
</div>
```

## Comparing two periods

Analytics reports compare a range with another one. In `range` mode, `compare-from` and `compare-to` hold that
comparison range, drawn as a band under its days (`--c2-date-selector__compare--background`, `--…__compare--height`)
while the range keeps its own fill, and announced as each day's description. `compare="previous-period"` derives it
from the range, as many days ending the day before `from`; `compare="previous-year"` takes the same dates a year
earlier (February 29 becomes February 28). A preset follows every new range and clears the band while the range is
incomplete. To let the user pick the comparison range, set `editing="compare"`: clicks and the keyboard then set
`compare-from` and `compare-to` instead, and a preset becomes `compare="custom"` so a later range does not overwrite it.
Read the comparison range from the `compareFrom` and `compareTo` properties: unlike `from` and `to`, they are not
reflected to attributes, because a preset derives them as the element upgrades.

The `change` detail adds `compareFrom` and `compareTo` while a comparison is in use, and with `name="period"` a complete
comparison range is submitted as `period-compare` and `period-compare-end`. The toggle that switches the comparison
belongs to the app: put a `c2-select` or a `c2-switch` in the `footer` slot and set `compare` from it, listening on
the control itself (its `input` and `change` stop at the footer, so the selector's own events stay its own). Turning the
comparison off is `compare = ''` with `compareFrom` and `compareTo` emptied. The
[gallery](/web-components/components/date-selector/gallery) has a working toggle.

```html tag=UsageBlock,package=@c2n/date-selector
<div data-label="Compared with the previous period">
  <c2-date-selector months="1" from="2026-09-14" to="2026-09-20" compare="previous-period" locale="en-US" aria-label="Report period"></c2-date-selector>
</div>
```

## Limiting the date range

`min` and `max` are inclusive `YYYY-MM-DD` bounds. Days outside them are greyed out (`--c2-date-selector__day__disabled--opacity`) and cannot be clicked or reached with the keyboard, and the previous/next month buttons are disabled once the next month would hold no selectable day. For a range relative to today, compute the bounds when the page loads — the examples below do so from `data-min-days` / `data-max-days` offsets:

```html tag=UsageBlock,package=@c2n/date-selector
<div data-label="From two days ago (d-2 onwards)">
  <c2-date-selector months="1" data-min-days="-2" locale="en-US" aria-label="Choose service dates"></c2-date-selector>
</div>
<div data-label="Past dates only (up to d-1)">
  <c2-date-selector months="1" data-max-days="-1" locale="en-US" aria-label="Choose a past period"></c2-date-selector>
</div>
```

Build the bounds from the local date parts rather than `toISOString()`, which is UTC and can land on the wrong day:

```ts tag=CodeBlock
import type { DateSelector } from '@c2n/components/date-selector'

function isoDaysFromToday(offset: number) {
  const date = new Date()
  date.setDate(date.getDate() + offset)
  const month = String(date.getMonth() + 1).padStart(2, '0')
  const day = String(date.getDate()).padStart(2, '0')
  return `${date.getFullYear()}-${month}-${day}`
}

const booking = document.querySelector<DateSelector>('#booking')!
booking.min = isoDaysFromToday(-2) // d-2 and later

const history = document.querySelector<DateSelector>('#history')!
history.max = isoDaysFromToday(-1) // d-1 and earlier: past dates only
```
