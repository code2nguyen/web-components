`c2-image-annotator` is the markup step of a bug report, a support ticket or a design review: point at what is wrong with an arrow or a box, number the steps, write a note, and blur or redact what should not be shared, then export the result.

## Import

```typescript tag=CodeBlock
import '@c2n/components/image-annotator'
```

### Tools

The toolbar offers Select, Arrow, Line, Rectangle, Ellipse, Pen, Text, Number, Blur and Redact, a row of colours (`colors`), three stroke widths, and Undo and Redo (also Ctrl/⌘+Z and Shift+Ctrl/⌘+Z). Drag to draw; click to place text or a number. Shift keeps lines at 45° steps and boxes square. Select moves a shape, resizes it by its handles, and deletes it with Delete or the toolbar button.

### Shapes and export

Shapes are plain objects in the image's own pixels, so they stay in place at any display size. Read or set them with `shapes`; `annotation-change` gives the list after every edit, ready to save with the ticket:

```typescript tag=CodeBlock
const annotator = document.querySelector('c2-image-annotator')!
annotator.addEventListener('annotation-change', (event) => draft.save(event.detail.shapes))
const blob = await annotator.toBlob() // PNG at the image's natural size
```

`toBlob()`, `toDataURL()` and `toCanvas()` draw the image at full size with the shapes on it. Redactions are drawn above every other shape, so a later blur never uncovers them. In the export a redaction replaces the pixels and a blur is a coarse pixelation, so text under either cannot be recovered; use Redact for passwords, keys and card numbers. An image from another origin can only be exported with CORS: set `crossorigin="anonymous"` and serve it with `Access-Control-Allow-Origin`. Otherwise the export rejects and `annotator-error` says why.

### Keyboard

With a drawing tool chosen, Enter on the image adds a shape in the middle. With Select, Tab reaches each shape (named "Rectangle 1 of 3"), the arrow keys nudge it (Shift for 10 pixels), Enter edits a text, and Delete removes it. Additions and deletions are announced. `readonly` shows the shapes with no toolbar, for the ticket view.

### Review, pins and comments

`active` is the chosen shape, the same selection the Select tool makes: it is outlined, brought into view when the app changes it, and `shape-select` reports every choice the person makes (a click, Tab, the arrow keys, a new shape) with the shape itself. `readonly selectable` keeps the shapes choosable without editing them: the arrow keys walk them, Escape clears the choice. That is the review mode of an extraction and of a pinned plan, and `--c2-image-annotator__shape__inactive--opacity` dims the other shapes around the active one.

Every shape can carry a `label` (what it marks, read after its kind) and a `confidence` from 0 to 1. Below `confidence-threshold` (0.8) the outline turns to `--c2-image-annotator__low-confidence--color` and dashes, and the shape is announced as needing review. The form that corrects the values is the app's: make the focused field's region active, and step with `next()` and `previous()`.

```typescript tag=CodeBlock
form.addEventListener('focusin', (event) => (annotator.active = event.target.dataset.field ?? null))
acceptButton.addEventListener('click', () => fieldFor(annotator.next())?.focus())
```

Beside the active shape sits a card (`part="detail"`) holding the `detail` slot: put a `c2-comment-thread` there and swap its comments on `shape-select` for pinned comments, where the Number tool drops each pin. With nothing slotted, `renderDetail` draws the card from `{ shape, index, count }` instead. Enter on the active shape moves the keyboard into the card and Escape brings it back; keys typed in the card (Delete, Ctrl/⌘+Z) are left to it.

```typescript tag=CodeBlock
annotator.addEventListener('shape-select', (event) => {
  if (event.detail.id) thread.comments = threads[event.detail.id] ?? []
})
annotator.renderDetail = ({ shape }) => html`<strong>${shape.label}</strong>`
```
