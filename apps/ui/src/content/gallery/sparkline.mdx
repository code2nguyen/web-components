## Realtime market table

`c2-table` calls its item-rendering hook `renderCell`. The trend column returns a real `c2-sparkline` for each row. The table's `animate-updates` feature matches each replacement row by `row-key` and interpolates its numeric fields over `update-duration`. Because `renderCell` and `rowStyle` receive those intermediate rows, the visible price, newest sparkline point, persistent threshold background and percentage move together. Rows at or below 30% of their day range stay softly red, rows at or above 70% stay green, and the middle stays neutral. Every third tick also adds or removes an instrument; additions expand in and removals collapse out.

The starting watchlist is a fixed illustrative snapshot for a repeatable demo. Subsequent 1.2-second targets are deterministic local simulation—not a live trading feed. Only rendered rows are interpolated, so the feature keeps the table's virtualization model and does not walk an off-screen dataset on every animation frame. It also honors the user's reduced-motion preference.

The essential renderer and update loop are:

```js tag=CodeBlock
trendColumn.renderCell = ({ row }) => html`
  <c2-sparkline .data=${row.history} tone="auto"></c2-sparkline>
`

table.animateUpdates = true
table.updateDuration = 720
table.rowStyle = ({ row }) => ({
  background: priceBandColor(row.price, row.low, row.high),
  transition: 'background 240ms ease-out',
})

// The snapshot may add, remove, or modify rows. The table owns every transition.
table.rows = nextMarketTick(table.rows)
```
