# Icon sets

Guidance for `packages/icons/*`. Claude Code loads this file when it works in this directory; the repo-wide rules are in the root `CLAUDE.md`. Paths are relative to the repository root.

`packages/icons/*` — icon-set packages, one per upstream icon library (`feather-icons` → `@c2n/feather-icons`, `phosphor-icons` → `@c2n/phosphor-icons`), plus the hand-drawn `symbols` set below. Same depth and config shape as `packages/components/*`. Each ships **one Lit element per icon** (`c2-feather-<icon-name>`), all extending a hand-written base class (`src/feather-icon.ts` + `.scss`) that owns the `<svg>` wrapper and the shared `--c2-feather-icon--{size,color,stroke-width}` theme. The per-icon files in `src/icons/`, the `src/index.ts` barrel and `src/icon-names.ts` are **generated and committed**: `npm run generate -w packages/icons/feather-icons` runs `scripts/icon-generator/index.ts` (plain `node` on Node 24 type stripping — erasable TS syntax only), which reads `dist/icons/*.svg` from the `feather-icons` devDependency and formats output with prettier. Re-run it and rebuild after bumping `feather-icons`; never edit generated files by hand. The Vite config builds one entry per icon (`@c2n/feather-icons/icons/<name>.js`) plus the barrel, and a single `custom-elements.json` covers all icons. The doc page is `apps/ui/src/content/components/feather-icons.mdx` with `apps/ui/src/components/FeatherIconGallery.astro`.

- `packages/icons/symbols` → `@c2n/symbols` is the one package in that group **not** generated from an upstream library: spot illustrations for empty states, `c2-status-panel` media and error pages (`c2-symbol-<name>`, e.g. `c2-symbol-no-results`), drawn for this repo. The sources are committed `svg/<name>.svg` files (157 of them, 160×160, exact wrapper `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 160 160">`) plus `svg/catalog.json` (title, category `empty`/`status`/`error`/`security`/`commerce`/`communication`/`files`/`onboarding`, description — the description becomes each element's JSDoc, and so what the MCP registry searches). Every colour comes from a **colour-role class** — fills `backdrop`, `surface`, `muted`, `ink`, `primary`, `primary-soft`, `accent`, `success`, `warning`, `error`; the default outline `line`; coloured strokes `line-<role>` — which `src/symbol.scss` maps onto `--c2-symbol__<role>--color` (plus `--c2-symbol--size` and `--c2-symbol--stroke-width`). `npm run generate -w packages/icons/symbols` (`scripts/symbol-generator/index.ts`) rejects a `fill`/`stroke`/`style` attribute, an unknown class or element, and a `$theme` map that disagrees with its documented variable list, then writes `src/symbols/<name>.ts`, `src/index.ts` and `src/symbol-names.ts` (names + `symbolCatalog`). Import path is `@c2n/symbols/symbols/<name>.js`. The theme maps the roles in `overrides.ts`; accent, success and warning stay fixed. Symbols are decorative (`aria-hidden`) unless given a `label`. Docs: `apps/ui/src/content/icons/symbols.mdx` + `components/SymbolGallery.astro`; style contracts share the `symbol-base` path.

- `packages/icons/task-icons` → `@c2n/task-icons` is the second hand-drawn set: 191 duotone 24×24 icons for to-do items (`c2-task-icon-<name>`, e.g. `c2-task-icon-meeting`), built exactly like `symbols`: committed `svg/<name>.svg` sources plus `svg/catalog.json` (title, one of 15 subject categories, **keywords**), and `npm run generate -w packages/icons/task-icons` (`scripts/task-icon-generator/index.ts`) validates and writes `src/icons/<name>.ts`, `src/index.ts` and `src/task-icon-names.ts`. The styling contract is smaller: an element with no class is an outline in `currentColor`, `tone` adds the soft fill (`--c2-task-icon__tone--color`/`--opacity`), `fill` is the soft fill alone, `solid` a solid mark; any colour/stroke/style attribute is rejected. The hand-written `src/suggest-task-icon.ts` (`suggestTaskIcon(text)`) scores the catalog keywords against a task label, which is how `c2-todo-list` picks a list's header icon from its heading (task icons themselves are opt-in) — add keywords to the catalog rather than special-casing the function. Import path is `@c2n/task-icons/icons/<name>.js`. It is excluded from the umbrella like the other icon sets, but `@c2n/todo-list` depends on it and imports the whole barrel (its picker needs every icon). Docs: `apps/ui/src/content/icons/task-icons.mdx` + `components/TaskIconGallery.astro`.

## Adding an icon-set package

For a new icon-set package, copy `packages/icons/feather-icons` (the plop generator does not know about icon packages), swap the generator's upstream resolution and tag prefix, add `./packages/icons/<name>:build` to the root wireit list, and wire the demo manifest and doc page by hand.
