`c2-pivot-table` does what a spreadsheet's pivot does: it groups flat rows by the fields set on `rows` and `columns`, and aggregates the `values` in every cell, with a subtotal for each group and grand totals.

## Import

```typescript tag=CodeBlock
import '@c2n/components/pivot-table'
```

### Data and values

`data` is an array of plain rows (a dotted field such as `customer.country` reads a nested value). `rows` and `columns` list the grouping fields, outermost first; a missing value groups under "(blank)". Each `values` entry is `{ field, aggregate, label, format }`: the aggregate is `sum` (the default), `count`, `avg`, `min`, `max` or `distinct`, and `format` takes `Intl.NumberFormat` options. Two or more values split each column. `field-labels` names the fields in headers and in the field list.

### Financial statements

A `values` entry with `compute` is worked out from two other values of the same cell instead of the records: `{ "field": "variance", "compute": "difference", "of": ["actual", "budget"] }` is actual minus budget, `percent-difference` is that difference over the budget (shown as a percentage unless `format` says otherwise) and `ratio` divides them. Subtotals and totals compute from their own sums, so a section's variance % is not an average of its accounts'. `of` names the first aggregated value of each field, so the data holds the compared figures side by side (`actual` and `budget`, or this year and last year) in each record.

`invert-signs` lists row groups whose numbers count with the opposite sign, by field: `{ "section": ["Cost of sales"] }`. The sign flips before aggregation, so costs show negative, subtract in the grand total and an overspend reads as a negative variance. A computed cell carries the class `negative` or `positive`; colour them with `--c2-pivot-table__computed__negative--color` and `--c2-pivot-table__computed__positive--color`, and use `"currencySign": "accounting"` in `format` for parentheses.

`pivot(data, config)` is the same computation as a plain function, for a server, a test or an export.

### Groups, totals and sorting

Row groups expand and collapse from their header, by click or with Left and Right; `expand-depth` sets how deep they start open, and `expandAll()` / `collapseAll()` change it from code. An open group has its subtotal under it (`subtotals="top"` puts it on the group's own row, `none` drops it), and `totals` keeps the grand total row and column (`both`), one of them, or neither. Clicking a column header sorts the rows by it: largest first, then smallest first, then back to the labels. `heatmap` tints each cell by its value within its measure, the usual look for a cohort table.

### Field list

With `configurable`, a field list beside the grid holds the data's fields in four zones: unused, rows, columns and values. Drag a field between them, or use its menu, which also changes a value's aggregate. `pivot-change` gives the new `{ rows, columns, values }`, and the change is announced.

### Drill-down and export

`cell-click` gives the row and column paths, the value and the `records` behind a cell, to open them in a table or a sheet. `toCSV()` returns the grid as shown.

### Keyboard and screen readers

The grid is a `treegrid`: the arrow keys move between cells, Home and End go to the ends of a row (with Ctrl, of the grid), Left and Right close and open a group, and Enter on a value cell fires `cell-click`. Each row carries its level, position and expanded state. The grid renders every visible row: past a couple of thousand, keep groups closed.
