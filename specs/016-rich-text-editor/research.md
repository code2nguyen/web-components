Takeaways:

- Compact editors converge on **8–12 formats**: B, I, U, S, inline code, link, bullet and numbered list, quote, sometimes code block or one heading. No colours, fonts or alignment: that is the line between this component and `c2-page-editor`.
- Toolbar placement is **top** (forms, Gmail-era editors), **bottom** (chat and comment composers, Gmail today) or a **bubble** over the selection (Medium, Linear). All three are structural choices, so an attribute.
- Values are HTML almost everywhere; GitHub is the Markdown exception. In this repo both ProseMirror editors (`c2-page-editor`, `c2-notepad`) store Markdown with inline HTML for what Markdown lacks, and expose `toHTML()`. See the open question in the spec.
- Trix shows a form-associated custom element is the right shape; nobody else integrates with native forms.

## 2. Accessibility

- **Toolbar**: APG [toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/): `role="toolbar"`, a name ("Formatting"), `aria-controls` the content, **one tab stop** with roving tabindex, Left/Right (wrapping), Home/End. Mark and list buttons are toggles with `aria-pressed`, updated on every selection change; link and clear are plain buttons.
- **Content**: contenteditable with `role="textbox"`, `aria-multiline="true"`, a name (field label), `aria-describedby`, `aria-invalid`, `aria-readonly`, `aria-placeholder`.
- **Shortcuts users expect** (Tiptap, Gmail, GitHub, Slack agree): Mod+B/I/U, Mod+K link, Mod+Shift+7 numbered, Mod+Shift+8 bullets, Mod+E inline code, Mod+Z / Mod+Shift+Z, Shift+Enter soft break. Strikethrough has no standard: Tiptap Mod+Shift+S, Slack/Gmail Mod+Shift+X; the comment/email convention wins (**Mod+Shift+X**). Alt+F10 to the toolbar (Lexical, CKEditor, TinyMCE).
- **Tab must leave the field.** Inside a list Tab / Shift+Tab indent and outdent; Escape then releases focus so the next Tab leaves (Lexical's escape hatch). Never a keyboard trap.
- **Link editing**: a popover anchored to the selection, not a modal. URL field; Enter applies; Escape closes and restores the selection; an existing link offers edit and remove. `javascript:` and unknown schemes rejected, a bare domain gets `https://` (`safeHref` in `page-editor/src/schema.ts` already does exactly this).
- **Mobile**: a bubble toolbar fights the OS selection menu and the keyboard. Floating placement falls back to a fixed bar on coarse pointers; touch targets ≥44px.

## 3. Value, paste and sanitising

- **Output subset** (Trix's terse HTML is the model): `p`, `br`, `strong`, `em`, `u`, `s`, `code`, `a[href]`, `ul`, `ol`, `li`, `blockquote`, `pre`. No `style`, `class`, `span`.
- **Paste** goes through the schema, so anything outside it is dropped by construction. But Google Docs wraps the clipboard in `<b style="font-weight:normal" id="docs-internal-guid-…">` and marks real bold as `span style="font-weight:700"`; Word sends `mso-*` styles and `<o:p>` _(unverified detail)_. Paste rules must **map** inline styles (weight ≥600, italic, underline, line-through) to marks before discarding them, and unwrap the Docs `<b>`. Mod+Shift+V pastes plain text.
- **XSS**: a Markdown value has no executable surface, but `toHTML()` output is HTML that apps will inject into emails and pages; it is generated from the schema (never echoes input), and link `href`s go through `safeHref`. Consumers still sanitise server-side. The initial value comes from the `value` attribute/property, never from light-DOM children (Trix's warning).
- **Max length** counts text characters, not markup. Like `c2-textarea`: counter in the footer (hidden while a `c2-form-field` manages it), `tooLong` validity. Input past the limit is allowed but marked invalid (typing is never silently swallowed; a paste is never truncated mid-word) _(a choice; some editors block instead)_.

## 4. Edge cases

- **Empty**: Quill's empty `<p><br></p>` breaks `required` and dirty checks. An empty document is `value === ''`; placeholder and `valueMissing` follow from that. Whitespace-only counts as empty for `required`.
- **Auto-grow** between `--…__content--min-height` and `--max-height`, then scroll inside while the toolbar stays put.
- **read-only**: focusable and selectable, toolbar hidden, links open on click, value submitted. **disabled**: not focusable, dimmed, not submitted, toolbar inert; also from a disabled `<fieldset>`.
- **Narrow width**: the toolbar's tail collapses into a "More" menu button that stays in the roving order.
- **Extension points**: mentions and emoji are a trigger character + suggestion popup (Tiptap Suggestion, GitHub). Give the app a hook (event with the query and a caret rect) and an insert method rather than building a user picker in. Custom toolbar buttons via a slot (Trix `x-` actions, GitHub `data-md-button`).

## 5. What c2 already has

| Need                                    | Existing piece                                                                                                                                                                                                          |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ProseMirror setup, input rules, history | `c2-page-editor` and `c2-notepad` both depend on `prosemirror-{model,state,view,commands,history,inputrules,keymap,transform}` at the same ranges, so the umbrella already ships one copy.                              |
| Markdown ↔ doc, `toHTML()`              | `page-editor/src/markdown.ts` (GFM + inline HTML for underline/colour; parsing never throws) and `toHTML()` in `page-editor.ts`. The compact editor needs a subset of it: no tables, to-dos, colours, images, headings. |
| Mark names and format event             | `PageEditorMark` (`bold italic underline strike code`), `format-change` with `PageEditorFormat`. Reuse the vocabulary so the two editors read the same.                                                                 |
| `allowed formats` attribute             | `c2-page-editor`'s `blocks` attribute: space-separated names, menus and Markdown shortcuts offer only these, pasted blocks outside the list become text. Same semantics here.                                           |
| Safe links                              | `safeHref` (`page-editor/src/schema.ts`).                                                                                                                                                                               |
| Field protocol, counter, validity       | `FieldContextConsumer` (`@c2n/core/contexts/field.js`), `c2-textarea`'s counter and supporting-text look (`--c2-textarea__container--*` literals map to theme tokens).                                                  |
| Toolbar overflow menu, link popover     | `c2-menu` (`@c2n/menu`) and `c2-overlay` for the "More" menu and the link popover; `c2-text-field` for the URL field.                                                                                                   |
| Localised text                          | `defineMessages` / `LocalizeController` (`@c2n/core/localize.js`).                                                                                                                                                      |

Nothing in the repo is a compact formatted-text **field**: `c2-chat-input` is a plain textarea composer, `c2-page-editor` is a page with a `/` menu, `c2-notepad` is a themed paper surface.
