`c2-shortcut` turns key presses into actions. It renders nothing: one element holds every shortcut of an application
(or of one region) in its `bindings` list, and a single `shortcut` event tells you which one fired, so the app has one
listener and one `switch`. A binding can also click or focus another element through `for`, which needs no script at all.

## Installation

```bash tag=CodeBlock
npm install @c2n/shortcut
```

## Usage

Focus any switch in the demo, then press <c2-kbd>1</c2-kbd>, <c2-kbd>2</c2-kbd> or <c2-kbd>3</c2-kbd>. The bindings are
scoped to the demo, so these keys do nothing anywhere else on this page.

```html tag=UsageBlock,package=@c2n/shortcut
<style>
  .shortcut-demo {
    display: grid;
    gap: 10px;
    width: 280px;
    max-width: 100%;
    font-size: 14px;
    color: #18181b;
  }
  .shortcut-demo__row {
    display: flex;
    align-items: center;
    justify-content: space-between;
    gap: 16px;
  }
</style>
<div data-label="Scoped to a region">

    <c2-shortcut
      bindings='[{"keys":"1","for":"shortcut-demo-wifi","scope":".shortcut-demo"},{"keys":"2","for":"shortcut-demo-bluetooth","scope":".shortcut-demo"},{"keys":"3","for":"shortcut-demo-airplane","scope":".shortcut-demo"}]'
    ></c2-shortcut>
```

## One element for the whole application

List every shortcut once and switch on `detail.action`. Assigning a new array to `bindings` replaces them all, which is
how an app swaps its shortcuts per route.

```html tag=CodeBlock
<c2-shortcut
  id="shortcuts"
  bindings='[
    { "keys": "mod+k, /", "action": "search", "description": "Open search" },
    { "keys": "mod+s", "action": "save", "description": "Save" },
    { "keys": "g d", "action": "go-dashboard", "description": "Go to dashboard" },
    { "keys": "escape", "action": "close-panel", "scope": ".side-panel", "allowInInputs": true },
    { "keys": "alt+n", "for": "new-item", "description": "New item" }
  ]'
></c2-shortcut>

<script type="module">
  import '@c2n/shortcut'

  const shortcuts = document.querySelector('#shortcuts')
  shortcuts.addEventListener('shortcut', (event) => {
    switch (event.detail.action) {
      case 'search':
        openSearch()
        break
      case 'save':
        save()
        break
      case 'go-dashboard':
        router.go('/dashboard')
        break
    }
  })
</script>
```

From script, a binding can carry a `handler` instead of an action, and `entries` returns each binding with its
platform-aware `label` (`⌘K, /` on macOS, `Ctrl+K, /` elsewhere) for a cheatsheet:

```ts tag=CodeBlock
shortcuts.bindings = [...shortcuts.bindings, { keys: 'shift+?', handler: () => cheatsheet.show(), description: 'Show shortcuts' }]

for (const { label, description } of shortcuts.entries) console.log(label, description)
```

## Key syntax

| `keys`         | Meaning                                                                       |
| -------------- | ----------------------------------------------------------------------------- |
| `mod+k`        | ⌘K on macOS and iOS, Ctrl+K elsewhere                                         |
| `ctrl+shift+p` | Every modifier listed must be held, and no other                              |
| `mod+k, /`     | Alternatives, separated by commas                                             |
| `g d`          | A sequence: <c2-kbd>g</c2-kbd>, then <c2-kbd>d</c2-kbd> within one second     |
| `?`, `escape`  | Key names are `KeyboardEvent.key` values, case-insensitive                    |
| `plus`, `comma`, `space`, `esc`, `up` | Aliases for keys the syntax itself uses, and short names |

Letters and digits also match by physical key when the typed character is not plain ASCII, so `alt+k` works with
Option on macOS and on non-Latin layouts.

## Behaviour

- **Typing.** Bare keys (`/`, `?`, `g d`, `escape`) are ignored while focus is in an input, textarea, select or
  contenteditable, so typing a slash in a field does not open search. Strokes with Ctrl, ⌘ or Alt fire there too.
  `allowInInputs` lifts the guard for one binding.
- **Scope.** `scope: "parent"` limits a binding to focus inside the element's parent; any other value is a CSS
  selector matched against the focused element and its ancestors. When several bindings match, the most narrowly
  scoped one wins, across every `c2-shortcut` on the page, then the first one listed.
- **Firing.** The key event's default is prevented (`allowDefault` opts out), then `shortcut` fires on the element.
  Unless it is cancelled, the binding's `handler` runs and its `for` target is activated: a text field — native or a
  component wrapping one, such as `c2-text-field` — is focused, anything else is clicked.
- **Keys already handled.** A key another component has handled (it called `preventDefault()`, as a list does for its
  arrow keys) is left alone.
- **Held keys.** Auto-repeat is ignored unless the binding sets `repeat`.
- **Accessibility.** Each `for` target receives `aria-keyshortcuts` (unless it already has one) so assistive
  technology announces the shortcut. Show the shortcut visually with [`c2-kbd`](../kbd).
- **Pausing.** `disabled` on the element pauses all of its bindings; `disabled` on a binding turns that one off.
  Removing the element unregisters everything.
