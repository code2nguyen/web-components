# @c2n/framework-types

Guidance for `packages/tools/framework-types`. Claude Code loads this file when it works in this directory; the repo-wide rules are in the root `CLAUDE.md`. Paths are relative to the repository root.

`packages/tools/framework-types` — published `@c2n/framework-types`, and the generator behind every piece of framework glue in the repo. `scripts/framework-types/` (Node 24 erasable TS, prettier-formatted output) reads every `@c2n/*/custom-elements.json` of the workspace packages (`pnpm-workspace.yaml`, through `@c2n/config/workspace.js`) and writes: **`<package>/react.d.ts` + `react.js`** (JSX `IntrinsicElements`, props derived from the element class), **`<package>/vue.d.ts` + `vue.js`** (Volar `GlobalComponents`, plus a `slot` widening of Vue's `HTMLAttributes`, which omits it), **`packages/adapters/angular/src/value-accessors.ts`**, **`tsconfig.vue.json`** (the `vueCompilerOptions` a Vue app extends: `strictTemplates` and the `experimentalModelPropName` map so `v-model` binds `value`/`checked` instead of `modelValue`) and **`dist/{html-custom-data,web-types}.json`** for VS Code/Volar and the JetBrains IDEs, plus the whole of `packages/umbrella` (`@c2n/components`, below). The per-package files are **committed** next to `custom-elements.json`; only the two JSON files and the tsconfig fragment ship in the package itself. **Framework bindings:** a package that ships runtime code for a framework (hooks, composables) puts it in `src/react.ts` / `src/vue.ts`, adds that file to its Vite lib entries (→ `dist/react.js` / `dist/vue.js`, declarations in `types/src/`) and lists the framework as an optional peer; the generator then makes the package's `react.js`/`vue.js` and `.d.ts` `export *` from it next to the JSX/`GlobalComponents` augmentation (so `import { useRenderedRows } from '@c2n/table/react'` is the hook and the types in one import), and the umbrella's `/react`/`/vue` re-export it too (`bindingPaths()` in `manifests.ts`; a source without its build output fails the run). No other entry of the package may import the framework. The build then compiles every generated `react.d.ts`/`vue.d.ts` with `skipLibCheck` off (`check.ts`, only diagnostics inside those files count), because a consumer's `skipLibCheck` turns a broken declaration into silent `any`. Vue event handlers read their type through `EventMapOf<Class>` from `@c2n/core/event-helper.js`, so an inherited map (`ChartEventMap` on every chart) or one the package root does not export works without importing it by name. Which elements count as form controls is one predicate, `formControlModel()` in `manifests.ts` (a `name` attribute plus `value`/`checked` plus `input`/`change`), shared by the Vue and Angular emitters. Not in the root `wireit.build` list (its build depends on that group): it runs from `pnpm run build:tools`, and `deploy.yml`'s `git diff --exit-code` step covers its output.
